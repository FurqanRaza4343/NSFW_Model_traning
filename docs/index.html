Image Moderation API

Send an image, get a decision. The API checks pictures for nude and explicit content and answers approve, review or reject in about a second, so your website or app can decide whether to publish the image.

Simple REST API

One endpoint, one image upload, one JSON answer. Works from any language, server or mobile app.

Three models, one decision

An ensemble of three open models. The most cautious answer wins, so one model's miss is caught by another.

Nudity is never auto-approved

Explicit and artistic nudity is rejected or sent to review. Borderline images go to a human, not to your users.

Free trial, then your own key

Register for a small free trial. An access code from the owner unlocks unlimited use, and keys can be revoked at any time.

Private by design

Rejected images are never kept. Approved or review images of consenting users are deleted after __RETENTION__ days. Logs hold scores and fingerprints only.

Fail-private contract

The API is built around one rule: if anything goes wrong, keep the image private.

How it works

1. Your app sends the image + your API key  -->  POST /v1/moderate
2. The API checks the key and your rate limit
3. Three models look at the image
4. You get a JSON decision back:
     approve  -> publish the image
     review   -> hold it for a human moderator
     reject   -> keep it private

Quickstart

  1. Get an API key. Open the web UI, register (name, email, optional phone), go to the API access tab and click Generate my key. Copy the key: it is shown only once. You get a free trial of __TRIAL__ checks; an access code from the owner unlocks unlimited use.
  2. Send an image. 
    curl -X POST "__BASE_URL__/v1/moderate" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "file=@photo.jpg"
  3. Act on the decision. approve → publish, review → send to a moderator, reject → keep private. On any error, keep the image private.

Authentication

Every request to /v1/moderate and /v1/usage needs an API key in the Authorization header:

Authorization: Bearer mod_live_xxxxxxxxxxxxxxxxxxxxxxxx
  • Customer keys start with mod_live_. They can be restricted to certain websites. A free-trial key allows __TRIAL__ checks in total; a key unlocked with an access code, or created by the owner, can be unlimited or have custom limits.
  • Getting a key: register in the web UI and generate it in the API access tab, or ask the service owner for a key with custom limits.
  • Only a hash is stored. The plain key is shown once at creation and cannot be recovered. If you lose it or it leaks, ask for it to be revoked and create a new one.
  • Revocation takes effect within about 30 seconds.

Keep keys secret. Call the API from your own backend server whenever possible. A key placed in website JavaScript or inside a mobile app can be extracted by anyone who inspects it. If you must call from a browser, create the key with allowed websites, so browser requests from other sites are rejected. This does not stop non-browser clients, so keep the per-key limits in mind.

Allowed websites (origin lock). When a key has allowed websites, a request that carries an Origin header (all browser requests do) is accepted only if that origin is on the list. Otherwise the API returns 403. CORS is enabled for the API, so browsers can call it directly.

Decisions & scores

The decision comes from two scores:

ConditionDecisionWhat your app should do
nsfw_score ≥ __REJECT__rejectDo not publish. Keep private or delete.
nsfw_score ≥ __REVIEW__, or suggestive_score ≥ __SUGG__reviewDo not publish yet. Send to a human moderator.
otherwiseapproveSafe to publish.
  • Policy: nudity, including artistic nudity, is never auto-approved.
  • Clearly safe images usually score low. Values close to 1 mean the model is very sure.
  • Sports and beach photos (swimwear, shirtless people) can land in review. This is intended: borderline images should be checked by a person.
  • Do not build your own thresholds on nsfw_score unless you have tested them on your own images. Use decision.

These classifiers are not perfect. Expect some false positives (safe images flagged) and rare false negatives. Keep a human review path for the review decision.

Code examples

Replace YOUR_API_KEY with your key. All examples post the image as a form field named file and read the decision.

The Kotlin, Flutter and Swift snippets follow each platform's standard multipart pattern, but they were not compiled for this documentation. Adapt them to your project.

Server-side wrapper that fails private (Python)

import requests

def check_image(path):
    """Returns 'publish', 'pending_review', 'rejected' or 'private'."""
    for attempt in range(3):
        try:
            with open(path, "rb") as f:
                r = requests.post("__BASE_URL__/v1/moderate",
                                  headers={"Authorization": "Bearer YOUR_API_KEY"},
                                  files={"file": f}, timeout=60)
        except requests.RequestException:
            continue                              # network problem: retry
        if r.status_code == 200:
            return {"approve": "publish", "review": "pending_review",
                    "reject": "rejected"}.get(r.json()["decision"], "private")
        if r.status_code == 429:
            import time; time.sleep(int(r.headers.get("Retry-After", 5)))
        elif r.status_code < 500:
            return "private"                      # 400 / 401 / 403: retrying will not help
    return "private"                              # anything unclear: never publish

Best practices

  1. Call from your backend. Keep the API key on your server. Your website or app uploads the image to your server, your server calls this API.
  2. Fail private. Publish only on a clear approve. On timeouts, errors or unknown responses, keep the image hidden.
  3. Hold review images. Show them to a moderator queue before publishing.
  4. Use a 60-second timeout and retry with backoff on 5xx errors and network failures. Respect Retry-After on 429.
  5. Resize large photos on the client before upload. A 1-2 MB image is plenty for moderation and uploads faster.
  6. Store the decision with your image record (decision and scores) so you can audit or re-review later.
  7. Do not hammer the API. Moderate each image once, at upload time.
  8. Re-check your thresholds if you change policy: ask the service owner, who can tune them on a sample of your own legal images.

The models

Every image is checked by three independent open-source models (all Apache-2.0 licensed). No image is sent to any outside AI service. The most cautious answer wins, because each model has blind spots. In one real test, a semi-nude artistic photo scored only 0.0005 from the first model (a miss), but 0.74 from the second and an adult score of 0.9998 from the third.

Security & privacy

  • What is kept. For every check: the decision, scores, image size and a SHA-256 fingerprint (not the picture). The image itself is kept only for registered users and for keys the owner enabled, only when it was approved or flagged for review, and for at most __RETENTION__ days. Rejected images are never kept.
  • Logs contain no images or file names. Only the decision, scores, key name, image size and timing are logged, for monitoring.
  • Keys are stored as hashes and are never shown again after creation.
  • HTTPS only. All traffic is encrypted in transit.
  • Rate limits and revocation protect the service. A leaked key can be revoked without affecting other customers.
  • Legal content: only upload images you are allowed to process. You are responsible for the images you send.

FAQ

Why was my safe image sent to review?

Swimwear, shirtless people, sports and some artwork look similar to nudity to the models. The policy is to let a person decide instead of auto-approving borderline images.

Why is the first request so slow?

The service shuts down when idle to save resources. The first request after a quiet period starts it and loads the models (10-15 seconds). Later requests take about 1-2 seconds.

Can I moderate video?

No. Only still images. For video, send extracted frames. Animated GIFs: only the first frame is checked.

Which image formats work?

JPEG, PNG, WebP, BMP, GIF and TIFF, up to __MAX_MB__ MB and __MAX_MP__ megapixels.

Can I call the API directly from JavaScript in the browser?

Technically yes (CORS is enabled), but the key becomes visible to anyone. Prefer your backend. If you must, restrict the key to your website and keep its limits low.

How do I get more than the free trial?

Ask the service owner for an access code (unlimited use) or for a key with custom limits.

What personal data do you store?

When you register in the web UI we store your name, email and optional phone number to give you access and to contact you about this project. Images you upload are checked in memory; approved or review images may be kept for up to __RETENTION__ days (rejected images are never kept). To have your data and images deleted, contact the owner.

What happens if I lose my key?

It cannot be recovered. Ask for the old key to be revoked and generate a new one.

Is the decision always correct?

No. This is a statistical classifier. Use the review path and keep a human in the loop for sensitive decisions.
